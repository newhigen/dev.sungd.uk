<p class="q">커밋 42개, 손댄 날은 닷새.</p>

9월 8일에 도서관 판부터 세우고 열흘을 묵혔다가, 25일에 다시 잡아 사흘 만에 지금 모양이 됐다.
그 사흘에 바뀐 것이 크다 — 도서관 자료를 공개 API 에서 홈페이지 직접 조회로 갈아 끼웠고,
지도를 버리고 노선도로 갔고, 중고매장 값을 「가서 확인」에서 실제 값으로 바꿨다.

막힌 것은 대체로 **남이 준 데이터를 믿은 자리**였다. 같은 책에 다른 답을 주는 공개 API,
판매량이 반영된 검색 순서, 검색 결과 블록에 안 들어 있는 재고. 그리고 하나는 내가 잘못
잰 것이었다.

## 노선 하나로 재면 거리가 틀린다

<Fig src="/p/book-hunt/lines.svg"
  alt="중고매장 세 곳의 거리를 9호선만 볼 때와 환승 노선까지 볼 때로 견준 막대"
  caption="목동점은 선 밖이라 판정했던 곳이고, 영등포점은 아예 뺐던 곳이다." />

중고매장을 고를 때 「지나는 길인가」를 9호선 역과의 거리로 쟀다. 그런데 김포공항은 5호선도
지난다. 5호선을 넣자 목동점이 1.80km 에서 0.51km 가 됐고, 뺐던 영등포점이 0.58km 로 들어왔다.
목동점은 이미 넣어 둔 게 결과적으로 맞았지만 근거는 틀렸었다.

## 배운 점

- **남이 준 데이터는 그 사람 기준으로 정렬돼 있다.** 검색 순서는 판매량과 광고를 반영하고,
  공개 API 는 답이 갈렸다. 내 기준이 따로 있으면 받아서 다시 세워야 한다.
- **예시 값에도 진짜 링크를 붙여 본다.** 링크가 없을 때는 틀린 값이 안 들킬 뿐이지 처음부터
  틀린 값이었다.
- **거리는 갈 수 있는 길로 잰다.** 노선 하나로 재면 실제 동선과 어긋난다. 환승역이 있는
  구간은 지나는 노선을 다 넣어야 한다.
- **값이 없는 것과 못 읽은 것은 다르다.** 교보에서 값이 안 보인 건 파싱이 틀려서가 아니라
  품절이어서였다. 둘을 같게 다루면 화면이 거짓말을 한다.
